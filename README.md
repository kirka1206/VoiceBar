# VoiceBar

Нативное приложение-утилита для macOS: диктовка заметок и промптов через локальный `whisper.cpp`. Запись, история и распознавание остаются на Mac. Микрофон и системный звук можно включать по отдельности или вместе.

## Требования

- macOS 14.2 или новее;
- полный Xcode с активным developer directory;
- CMake 3.24+;
- доступ к GitHub для сборки закреплённой версии `whisper.cpp` и к Hugging Face для первой загрузки модели;
- для сборки Metal-бэкенда доступна утилита `metal` из Xcode.

## Сборка приложения

```sh
brew install cmake
./scripts/build-app.sh
open dist/VoiceBar.app
```

Скрипт собирает локальную динамическую библиотеку на базе `whisper.cpp` v1.8.2 с Metal и помещает её внутрь приложения. На первом запуске приложение загружает мультиязычную модель `large-v3-turbo` (около 1,5 GiB); дальше распознавание выполняется локально.

При запуске откроется окно истории, а VoiceBar останется доступен в строке меню. По умолчанию для диктовки используется `Control+Option+Space`: поставьте курсор в поле нужного приложения и нажмите сочетание, чтобы начать, затем повторите его для остановки и вставки. В настройках можно назначить другое сочетание или выбрать режим «удерживать для диктовки» — запись остановится при отпускании клавиш. То же действие доступно кнопкой в окне истории или меню VoiceBar. Там же выбираются микрофон или системный звук, язык и режим автовставки.

При первом запуске VoiceBar загружает модель; после этого распознавание работает офлайн. Разрешите доступ к микрофону и/или системному аудиозахвату, когда macOS запросит его. Автовставка требует системного разрешения на отправку событий. Если приложение назначения сменилось или разрешение не выдано, VoiceBar оставит текст в буфере и истории.

В настройках на вкладке «Словарь» можно указать англоязычные термины вручную, импортировать `.txt`-файл или выбрать документы для извлечения предложений: `.txt`, `.md`, `.csv`, `.rtf`, `.doc`, `.docx` и PDF с текстовым слоем. Для каждого предложения показываются число упоминаний и фрагмент исходного текста; пользователь может отредактировать, выбрать и подтвердить термины. Сканированные PDF не проходят OCR. Несколько документов обрабатываются локально; VoiceBar не сохраняет исходный файл или полный текст в истории и не отправляет содержимое по сети. При выборе файла из iCloud Drive или другого File Provider macOS может скачать его после подтверждения выбора.

Добавление из файлов и обычный импорт `.txt` дополняют текущий список и не дублируют термины с тем же написанием без учёта регистра. Перед передачей словаря движок считает токены готовой подсказки своим Whisper-токенизатором и показывает использование относительно лимита текущей модели. Сохранённые термины не обрезаются: если лимит превышен, VoiceBar просит сократить список и блокирует начало записи. Словарь может помочь сохранить написание названий вроде `VMware` и `Kubernetes`, но не гарантирует правильное распознавание.

Во вкладке «Исправления» можно задать пары `вариант распознавания => правильное написание` или загрузить их из `.txt`. Правила применяются к целым словам и фразам до сборки расшифровки; при совпадении нескольких правил используется самое длинное. Импорт сохраняет существующее правило при конфликте и показывает конфликтующую строку. Частые неоднозначные русские слова не заменяются автоматически.

## Проверки

```sh
swift test
```

Изолированный U2-эксперимент с уже установленной локальной моделью Ollama запускается так:

```sh
swift run TranscriptCorrectionEvaluation --model gemma4:latest
```

Он использует только синтетические тексты и локальный API на `127.0.0.1`; модель не загружается. Отчёт по умолчанию записывается в `/tmp/voicebar-transcript-correction-report.json`. Эксперимент не подключён к производственному пути распознавания.

Проверка распознавания и real-time factor требует полной сборки движка, загрузки модели и живого аудио на целевом Mac. Аудиозаписи VoiceBar не сохраняет.
